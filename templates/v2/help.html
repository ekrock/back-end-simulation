Quick Start

  1. Download the CSV template, or one of the scenario files.
  2. Edit it to define AMR types/fleet, cells, external parts, and jobs with their steps.
  3. Upload the CSV on the V2 home page and click Run Simulation.
  4. Explore the results: run summary, per-job lateness, cell/station/AMR utilization, and the full event log.

Scheduling Policies

FIFO. Iterates pending jobs in file order and assigns each to the first placeable (Idle, capable) cell in [CELLS] file order. A job with no placeable cell is skipped this tick and reconsidered next tick.

EDD (earliest deadline, earliest estimated completion). Iterates pending jobs sorted by deadline (ties broken by file order), and for each picks the placeable cell with the lowest estimated completion tick — accounting for AMR lead time to set up, the job's pipeline fill time, its per-unit cycle time, and the final pickup trip. A transparent greedy heuristic, not globally optimal.

Preemption (optional)

Set preemption_enabled,true in [SIMULATION] to let the orchestrator interrupt an in-progress job for a more urgent one, layered on top of whichever scheduling policy is chosen. Only applies to single-step ("simple") jobs, on both sides — a job is never considered as an incoming candidate or as a victim if it has more than one step.

The first tick a simple job is pending with no idle capable cell, it is evaluated exactly once: for each capable cell running an eligible in-progress job, the orchestrator projects when that job would naturally finish (from its observed ticks/unit so far, or the nominal cycle time if no unit has completed yet) and estimates the new job's completion if it waited for that cell. If waiting would meet the deadline on any candidate cell, nothing happens. Otherwise, it checks whether preempting the best candidate would meet the deadline; if so, it hands that cell to the new job immediately, and if not, it does nothing (waiting or preempting are both futile, so the job is left to run late).

Preempting a cell scraps only the victim's undelivered line-side buffer (an AMR carries it back to the warehouse as a background trip, logged as parts_returned — it doesn't gate the handover); everything the victim already delivered stays counted. The victim returns to the pending pool with its progress intact and is rescheduled normally afterward, same as any other pending job.

Job Splitting (optional)

Set job_splitting_enabled,true in [SIMULATION] to let a single-step ("simple") job run across several cells at once instead of just one. The first tick such a job is pending with at least one idle capable cell, it is evaluated exactly once: the orchestrator estimates completion on the best single idle cell (same formula EDD and preemption use). If that meets the deadline, nothing changes -- the job runs on one cell as usual.

If one cell isn't enough, it tries splitting across 2, then 3, and so on, up to however many capable cells are currently idle -- each split gets an even share of the units -- and stops at the smallest number of cells whose worst-case completion meets the deadline. If even using every idle cell still wouldn't make it, it uses all of them anyway (best effort).

A split job is internally represented as hidden, single-cell "shards" (e.g. BigJob#1, BigJob#2) -- ordinary jobs in every respect, visible in the raw event log, but rolled up into a single row on the results page and in results.json (cell shows every cell used; completion is the latest shard to finish).

Replenishment Policies

UnitsLeft,v. A station requests more parts when its line-side buffer has v or fewer units remaining. UnitsLeft,0 is the fully reactive baseline: it only asks once the buffer is empty.

PercentLeft,p. Requests when the buffer has p% or less of its capacity remaining.

PredictedOut,m. Projects depletion from the round-trip lead time of the slowest AMR in the fleet and the cell's per-unit cycle time, and requests early enough that a delivery should arrive with m units of safety margin still on hand — before the station ever starves, when the AMR fleet has slack.

CSV Format

The CSV is divided into named sections, each starting with a header row like [SIMULATION]. Blank lines are ignored, and lines beginning with # are comments.

[SIMULATION]

FieldDescription
nameDisplay name for the simulation run.
descriptionOptional free-text description.
max_ticksHard stop tick count. Max: 50,000.
scheduling_policyFIFO or EDD.
replenishment_policyThree CSV fields: policy name and its value, e.g. replenishment_policy,PredictedOut,10.
preemption_enabledOptional, true or false. Default false. See Preemption below.
job_splitting_enabledOptional, true or false. Default false. See Job Splitting below.

[AMR_TYPES]

One row per AMR type. Header row type_name,units_carried,speed_m_per_s,cost_dollars is required.

[AMRS]

Fleet size per type. Header row type_name,count is required.

[CELLS]

One row per cell: cell_name,distance_meters,speed_factor,num_stations,lineside_buffer_size,output_buffer_size. speed_factor must be ≥ 0.1; 1.0 runs steps at their listed ticks, 1.4 means 40% slower.

[PARTS]

One row per external part name. External parts are infinitely available at the Central Store.

[JOBS]

job_name,product_name,units,arrival_tick,deadline_tick,capable_cells. capable_cells uses | as the separator, e.g. CellA|CellB. arrival_tick defaults to 0 if blank; deadline_tick is required.

[JOB_STEPS]

job_name,station_number,part_name,parts_per_unit,ticks[,min_available]. Rows for a job must be contiguous, station numbers ascending from 1. Every part must be listed in [PARTS], or be another job's product_name (an intermediate part). By default, a job that consumes an intermediate part becomes schedulable only after every job producing it has delivered all of its units to the store; the store tracks a finite count of intermediate parts, unlike external parts which are always infinite.

The optional 6th column, min_available, replaces that default with a quantity threshold: the dependent job becomes schedulable as soon as the store holds at least that many units of the intermediate part, even while the producing job is still running. Only valid on a step whose part is an intermediate part (not an external one).

Metrics

MetricDefinition
MakespanThe tick the run ends: all jobs complete and all AMRs idle, or max_ticks.
Total latenessSum over jobs of max(0, completion_tick − deadline_tick). Unfinished jobs use max_ticks as their completion tick.
Total starvation ticksSum over stations of ticks spent waiting for parts (Starving state).
Total blocked ticksSum over cells of ticks with zero stations Working, split by reason (starved vs. output buffer full).
AMR tripsCount of dispatched delivery, pickup, and (if preemption fired) return trips.
PreemptionsCount of jobs interrupted to hand their cell to a more urgent one.
Jobs split across cellsCount of jobs run as shards on more than one cell at once.
UtilizationWorking/Running/busy ticks divided by makespan, per station/cell/AMR.
