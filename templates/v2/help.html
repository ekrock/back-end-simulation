Quick Start

  1. Download the CSV template, or one of the scenario files.
  2. Edit it to define AMR types/fleet, cells, external parts, and jobs with their steps.
  3. Upload the CSV on the V2 home page and click Run Simulation.
  4. Explore the results: run summary, per-job lateness, cell/station/AMR utilization, and the full event log.

Scheduling Policies

FIFO. Iterates pending jobs in file order and assigns each to the first placeable (Idle, capable) cell in [CELLS] file order. A job with no placeable cell is skipped this tick and reconsidered next tick.

EDD (earliest deadline, earliest estimated completion). Iterates pending jobs sorted by deadline (ties broken by file order), and for each picks the placeable cell with the lowest estimated completion tick — accounting for AMR lead time to set up, the job's pipeline fill time, its per-unit cycle time, and the final pickup trip. A transparent greedy heuristic, not globally optimal.

Replenishment Policies

UnitsLeft,v. A station requests more parts when its line-side buffer has v or fewer units remaining. UnitsLeft,0 is the fully reactive baseline: it only asks once the buffer is empty.

PercentLeft,p. Requests when the buffer has p% or less of its capacity remaining.

PredictedOut,m. Projects depletion from the round-trip lead time of the slowest AMR in the fleet and the cell's per-unit cycle time, and requests early enough that a delivery should arrive with m units of safety margin still on hand — before the station ever starves, when the AMR fleet has slack.

CSV Format

The CSV is divided into named sections, each starting with a header row like [SIMULATION]. Blank lines are ignored, and lines beginning with # are comments.

[SIMULATION]

FieldDescription
nameDisplay name for the simulation run.
descriptionOptional free-text description.
max_ticksHard stop tick count. Max: 50,000.
scheduling_policyFIFO or EDD.
replenishment_policyThree CSV fields: policy name and its value, e.g. replenishment_policy,PredictedOut,10.

[AMR_TYPES]

One row per AMR type. Header row type_name,units_carried,speed_m_per_s,cost_dollars is required.

[AMRS]

Fleet size per type. Header row type_name,count is required.

[CELLS]

One row per cell: cell_name,distance_meters,speed_factor,num_stations,lineside_buffer_size,output_buffer_size. speed_factor must be ≥ 0.1; 1.0 runs steps at their listed ticks, 1.4 means 40% slower.

[PARTS]

One row per external part name. External parts are infinitely available at the Central Store.

[JOBS]

job_name,product_name,units,arrival_tick,deadline_tick,capable_cells. capable_cells uses | as the separator, e.g. CellA|CellB. arrival_tick defaults to 0 if blank; deadline_tick is required.

[JOB_STEPS]

job_name,station_number,part_name,parts_per_unit,ticks. Rows for a job must be contiguous, station numbers ascending from 1. Every part must be listed in [PARTS].

Metrics

MetricDefinition
MakespanThe tick the run ends: all jobs complete and all AMRs idle, or max_ticks.
Total latenessSum over jobs of max(0, completion_tick − deadline_tick). Unfinished jobs use max_ticks as their completion tick.
Total starvation ticksSum over stations of ticks spent waiting for parts (Starving state).
Total blocked ticksSum over cells of ticks with zero stations Working, split by reason (starved vs. output buffer full).
AMR tripsCount of dispatched delivery and pickup trips.
UtilizationWorking/Running/busy ticks divided by makespan, per station/cell/AMR.
